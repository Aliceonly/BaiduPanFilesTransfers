# BaiduPanFilesTransfers v2.8.4

## 批次中断后继续转存

- 批次因获取 `bdstoken` 失败、创建目标目录失败或未捕获异常中断后，按钮显示「继续转存」。
- 点击继续时从第一条未处理输入恢复，不重跑已经处理过的链接。
- 保留原批次的链接快照、日志、进度、指定目录编号、已分配目录和普通模式的成功记录。
- 恢复时重新建立 Session、获取 `bdstoken`，并读取更新后的 Cookie 和系统代理设置；链接、目标目录及模式沿用原批次。
- 连续恢复失败不清除断点。重复点击不会启动多个 worker；暂停后的继续仍使用原 worker。
- 先记录已完成任务的断点，再更新进度显示，避免显示异常导致恢复时重复转存。

单条链接的自动重试规则保持不变：网络异常、无效 API 响应及临时转存错误最多尝试 5 次，最终失败记录后继续下一条。已经记录失败的链接不属于待恢复任务，需要在本轮结束后单独重试。

**断点仅保存在当前程序进程的内存中，关闭窗口、程序崩溃或电脑重启后无法恢复。更新 Cookie 时请使用同一百度网盘账号。**

## 下载与使用

- `BaiduPanFilesTransfers.exe`：Windows x64 单文件程序，无需安装 Python。
- `BaiduPanFilesTransfers-windows-x64.zip`：包含 EXE、许可、使用说明、打包文档和构建信息。
- `BUILD_INFO.txt` 和 `SHA256SUMS.txt`：源码 Commit、构建依赖及文件校验值。

Release workflow 在 Windows runner 上执行 API mock 回归测试、源码 GUI 检查和打包后的 EXE 主窗口启动检查，通过后才发布。测试不访问真实百度网盘，实际账号与链接仍需自行验证。

目标平台为 Windows 10/11 x64，不保证 Windows 7 或其他 architecture 兼容性；程序未进行 Windows code signing。请在可写目录中运行，不要上传或分发包含个人 Cookie 的 `config.ini`。
